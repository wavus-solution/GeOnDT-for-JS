# GeOnDT for JS

**GeOnDT for JS는 웹 브라우저에서 3차원 공간 정보를 시각화하고 분석하는 JavaScript 제품입니다.** 지도·지형·시설물과 다양한 공간 데이터를 함께 표현하고, 사용자 조작과 업무 데이터를 연결하여 디지털 트윈 서비스를 개발할 수 있습니다. TypeScript 개발 환경에서 사용할 수 있는 타입 선언도 제공합니다.

GeOnDT로 다음과 같은 기능을 웹 서비스에 구성할 수 있습니다.

- **지도와 공간 데이터 시각화:** 영상 지도, 지형, 벡터 데이터와 3D 모델을 함께 표시합니다.
- **시설물과 객체 제어:** 시설물을 배치·선택·편집하고, 속성과 표시 상태를 바꾸거나 움직임을 표현합니다.
- **측정과 공간 분석:** 거리·면적 측정, 지형·토공량·가시권 분석 등을 사용자 화면과 연결합니다.
- **서비스 기능 조합:** 지도 이벤트, 데이터 조회, 분석 결과를 고객 서비스의 UI와 업무 흐름에 맞게 구성합니다.

이 공개 패키지는 개발자와 AI 작업자가 **GeOnDT를 이해하고, 사용자 요구에 맞는 기능을 찾아 서비스 코드를 작성하는 데 필요한 자료를 모은 참조 아카이브**입니다. 공개 소스와 인터페이스, 동작 명세, API 문서, 시작하기 안내와 공식 예제를 함께 제공합니다. 공개·비공개 분류가 진행됨에 따라 참고할 수 있는 공개 소스도 늘어납니다.

### 실제 서비스에서 사용하는 부분

사용자 서비스에 배치하는 제품은 **[dist](dist/)**입니다. 아카이브의 `src`·`markdown`·문서를 서비스에 설치할 필요는 없습니다. 일반 스크립트는 `GeOnDT.min.js`, ES 모듈은 `GeOnDT.modules.js`를 사용하며, TypeScript는 같은 배포본의 선언 파일을 사용합니다.

실행에 필요한 `GeOnDT.config.js`·worker·resource·wasm을 포함한 dist의 구조를 유지하십시오. 제품 연결과 지도 생성 방법은 위의 시작하기 안내와 공식 예제에서 확인할 수 있습니다. 이 아카이브에서 제품 엔진을 다시 빌드하는 절차는 제공하지 않습니다.

### 실행 가능한 시작 예제 선택하기

라이선스 로드, 제품 준비, 지도 생성·해제와 기본 오류 표시를 포함한 두 예제를 제공합니다. **두 예제 모두 같은 `GeOnDT.modules.js`를 사용하고 지도 기능도 같습니다.** 고객 앱을 작성하고 실행하는 개발 환경에 따라 하나를 선택하십시오.

| 구분 | [일반 ES 모듈 예제](starters/esm/) | [TypeScript / Vite 예제](starters/typescript-vite/) |
|---|---|---|
| 선택할 때 | JavaScript로 제품 연결을 확인하거나 일반 웹 페이지에 적용할 때 | TypeScript 타입 검사와 앱 빌드 환경이 필요할 때 |
| 수정할 앱 코드 | `src/main.js`, `src/settings.js` | `src/main.ts`, `src/settings.ts` |
| 실행 방식 | 작성한 JS를 브라우저에서 직접 실행 | Vite가 TS를 JS로 변환하고, 별도 명령으로 배포 `.d.ts`와 타입 검사 |
| 운영 배포 | HTML·CSS·JS와 준비된 제품 파일을 배치 | 앱을 빌드한 `build` 폴더의 내용물을 배치 |

**[내 PC에서 지도 띄우기 →](markdown/getting-started.md)** 선택한 예제의 명령을 따라 실행하면 지도를 확인할 수 있습니다. Node.js 22.12 이상과 npm이 필요하며, **기본 제공되는 `localhost` 도메인 라이선스를 사용합니다.**

다운로드한 아카이브에는 제품 `dist`와 라이선스 `starters/license.js`가 각각 한 벌씩 들어 있습니다. `npm run setup`을 실행하면 선택한 예제 안에 **`static` 폴더가 새로 생기고**, 제품과 라이선스가 실행용으로 복사됩니다. TypeScript 예제의 `node_modules`는 `npm ci`로, `build`는 `npm run build`로 생성됩니다. **이 세 폴더는 다운로드 시에는 없으며, 위 명령을 실행한 PC에 만들어집니다.**

처음 위치와 데이터 주소는 `settings`에서, 고객 기능은 `main`의 지도 준비 이후에 연결합니다. 기존 서비스가 있다면 예제의 라이선스·초기화·타입·리소스 연결 방식을 참고해 현재 프로젝트에 적용하십시오. 기능별 구현은 공식 예제와 API 문서에서 이어서 확인할 수 있습니다.

### 라이선스 요청과 적용

**`localhost` 도메인용 라이선스는 기본 제공됩니다.** 시작 예제는 제공된 [license.js](starters/license.js)를 사용하므로 로컬 실행을 위한 별도 발급·설정이 필요하지 않습니다. 예제의 로드 순서도 미리 구성되어 있습니다.

**다른 개발·운영 도메인에서 서비스할 때**는 다음 순서로 해당 도메인의 라이선스를 적용하십시오.

1. **라이선스 요청:** [GeOnDT 라이선스 요청 페이지](https://3d-wiki.geon.kr/?page_id=153)에서 요청합니다. 요청 시 **GeOnDT를 사용하는 웹 서비스의 개발 도메인과 운영 도메인**을 모두 전달하십시오.
2. **라이선스 로드:** 발급받은 라이선스 스크립트를 서비스에 배치하고, **GeOnDT 스크립트보다 먼저 로드**합니다. 아래는 발급 파일을 `license.js`로 배치한 일반 스크립트 방식의 로드 순서 예시입니다. 파일 경로는 실제 서비스 배치에 맞게 수정하십시오.

   ```html
   <!-- 발급받은 라이선스를 먼저 로드합니다. -->
   <script src="./license.js"></script>
   <!-- 라이선스 로드 후 GeOnDT를 로드합니다. -->
   <script id="GeOnDT" src="./dist/GeOnDT.min.js"></script>
   ```

   ES 모듈 방식에서도 `GeOnDT.modules.js`를 import하는 앱 진입 스크립트보다 라이선스 스크립트를 먼저 로드해야 합니다. 라이선스 스크립트에 `async`를 붙여 실행 순서가 바뀌지 않도록 하십시오.

3. **적용 확인:** 서비스를 실행하고 브라우저 개발자 도구의 **Console**에서 라이선스 인증 결과를 확인합니다. 정상 인증 시 다음 메시지가 출력됩니다.

   ```text
   GeOnDT for JS 라이센스 인증완료.
   ```

인증에 실패하면 라이선스 파일의 로드 여부·순서와 실제 접속 도메인이 발급받은 개발·운영 도메인에 해당하는지 확인하십시오. 라이선스 인증 이후에도 제품의 리소스 준비가 이어지므로, 지도 생성은 `GeOnDT.ready`에서 수행하고 초기화 실패는 `GeOnDT.fail`로 확인합니다.
