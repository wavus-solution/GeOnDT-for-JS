# UMeasureFeature 명세

> 상태: 구현 관찰 초안

## 목적과 책임

원본 피처와 그리기·검색용 데이터를 연결하는 매개체다. 원본 OpenLayers geometry와 셰이더용 좌표를 구분하며 타일의 GPU 자원을 직접 보유하지 않는다.

원본별 대표 `UMeasureFeature`는 원본 도형 조회와 변경 전달·스타일·강조 상태를 담당한다. 앱의 terrain manager는 레이어별 원본 등록부를 소유하며, 각 등록 항목에 대표와 WFS 표시 조각 목록·원본 요청·취소 제어·도형 소유권·변경 구독 해제를 함께 보관한다. manager 연결 전에는 레이어의 초기 등록부를 사용하고 연결 시 같은 Map을 복제하지 않고 인계한 뒤 레이어 필드를 제거한다. 대표는 WFS 표시 매개체 목록을 직접 보유하지 않는다. WFS 표시 조각은 `_sourceMeasure`로 같은 대표를 참조하며 각자의 좌표·경계·payload를 유지한다. 직접 추가한 runtime 원본은 자기 자신이 대표이고, 분할 표시에는 식별자·타입·좌표·구멍·그룹과 필요한 반경을 가진 자료를 사용한다. 이 자료마다 별도 `UMeasureFeature`를 생성하거나 부모의 스타일·변경 번호를 복사하지 않는다. 별도 `U2dVectorFeatureBinding`과 `_sourceBinding`·`_querySourceBinding` 경유는 사용하지 않는다.

## 공개 계약과 표시 데이터

- 생성자는 원본 참조, ID, 속성, 형상 유형, 좌표, 경계, 스타일과 변경 번호를 준비한다. 속성 접근자는 대응하는 조회·설정 메서드에 위임한다.
- `getOLFeature()`는 매개체가 보관한 원본 참조를 반환한다. 전체 WFS 원본을 연결한 대표는 OL Feature를, 표시 조각과 부분 타일 경로는 일반 데이터 객체를 보관할 수 있다. runtime 매개체는 등록 해제 후에도 사용자가 전달한 원본 OL Feature 접근을 유지한다.
- `getSourceFeature()`는 연결된 전체 원본이 있으면 그 Feature를, 없으면 기존 원본 참조를 반환한다.
- `getSourceGeometry()`는 이미 연결된 원본 `U2dGeometry`만 반환한다. 조회 자체로 도형이나 요청을 생성하지 않는다.
- `loadSourceGeometry()`는 등록 문맥의 원본 조회 창구를 통해 전체 도형을 준비하고 그 Promise를 그대로 반환한다. 같은 원본의 동시 요청과 완성된 도형은 재사용한다. 연결이 없거나 대표가 해제되었으면 undefined로 완료한다. 연결된 도형이 없고 전체 원본 제공 경로도 없으면 undefined로 완료하며, 원본 제공자가 실패하면 거부된 Promise를 반환한다.
- 기본 완전 WFS는 표시 분할 전에 타입별 원본 도형이 연결되어 있다. PBF·사용자 정의 부분 응답은 전체 원본 공급 전까지 도형 연결을 보류한다. `getSourceGeometry()`·`loadSourceGeometry()`로 원본을 외부에 제공한 상태와 검색으로 대표를 전달한 상태는 마지막 표시 해제 이후의 수명에 반영한다.
- `setStyle()`은 등록 문맥의 편집 창구에 원본 대표와 스타일을 전달한다. 표시 조각에서 호출해도 같은 대표를 사용하며 매개체가 레이어나 manager를 직접 호출하지 않는다. 내부 표시 상태를 반영할 때는 통지를 생략하여 원본 변경의 재귀를 막고, 원본 갱신 중의 통지는 전달하지 않는다. 등록되지 않은 단독 매개체는 자신의 스타일과 기존 원본 참조만 갱신한다. 해제된 대표나 안정 식별자가 없는 WFS 편집은 기존 오류로 거부하며 편집 창구의 오류는 호출자에게 전달한다.
- `changed()`는 연결된 원본의 `changed()` 또는 등록된 편집 창구를 통해 변경을 통지한다. manager 연결 경로에서는 등록된 구독이 변경을 모아 처리하며, 연결 없는 기존 경로는 원본의 `changed()`가 있으면 호출한다.
- `getGeometry()`는 원본 Feature의 OpenLayers geometry를 우선 반환한다. 타일 데이터 객체는 보관한 OpenLayers geometry를 반환한다. 원본의 `setCoordinates()`·`getExtent()`·`intersectsExtent()`를 덮어쓰거나 `getFeature()`를 추가하지 않는다.
- 기존 THREE 형상을 직접 전달하는 측정 경로에만 좌표·교차 판정 호환 메서드를 제공한다. OpenLayers 형상은 원본 메서드를 유지하며 타일 선택 동안만 별도 좌표 스냅샷을 재사용한다.
- `setGeometry()`는 보관한 형상과 연결된 OpenLayers Feature의 geometry를 교체하고 변경 번호를 갱신한다. `getMeasureVectors()`·`setMeasureVectors()`는 별도의 셰이더용 좌표를 조회·갱신한다.
- native `geometry.getExtent()`는 OpenLayers의 숫자 배열이고 `UMeasureFeature.getExtent()`는 표시 반경까지 반영한 기존 Box3다. 점 마커의 원본은 Point·MultiPoint이며 표시 좌표의 중심·가장자리로 반경을 표현한다.
- 경계·유형·ID·원본 참조·속성·검색 제외·변경 제한·그리기 순서의 조회·설정과 변경 번호의 비교·증가는 기존 기능을 유지한다.
- `updateMeasureData()`·`applyTypedMeasureData()`·`applyRuntimeState()`는 레이어가 계산한 표시 상태를 반영한다. 원본 참조를 먼저 교체한 뒤 geometry를 적용하며 빌린 OpenLayers geometry를 dispose하지 않는다.

## 수명과 검증

레이어는 원본 등록·해제 의도를 전달하고 manager는 등록부·변경 구독·갱신 병합의 수명을 관리한다. 원본 형상·스타일 동기화와 소유한 도형의 dispose는 레이어의 원본 처리 어댑터를 호출한다. 매개체는 레이어 또는 manager의 직접 참조 필드를 두지 않고 등록 문맥의 조회·편집 창구만 사용한다. 안정 식별자가 없는 타일 피처는 검색·선택만 지원하며 스타일 편집은 오류로 거부한다. 레이어 정리 후에는 원본 요청의 늦은 응답으로 도형을 생성하지 않는다. 해제 여부는 대표의 `_disposed` 상태로 판정하고 이후 편집을 거부한다.

마지막 표시 조각이 해제되면 자동 생성한 미편집·미노출 WFS 원본의 대표·도형·구독을 회수한다. 도형이 이미 있다는 이유만으로 원본을 보존하지 않는다. 개별 편집 스타일·내부 편집 표시·진행 중인 원본 요청·강조·외부 노출 등 유지할 상태가 있는 원본은 보존하며, 같은 원본 재수신에서도 객체와 편집 상태를 재사용한다. 회수된 원본의 재방문은 새 등록을 허용한다.

clear는 원본의 dispose 콜백 전에 manager의 이전 변경 예약을 무효화한다. 원본 정리 어댑터는 등록 항목을 먼저 제거한 뒤 요청 취소, 원본 변경·도형 해제 구독, 표시 조각 목록, 소유한 도형과 내부 표시 도형을 정리하고 편집 스타일·강조 참조를 해제한다. manager의 원본 소유자 해제는 남은 구독과 등록 항목의 정리를 실행한다. 매개체의 `_sourceContext`는 출처·원본 레이어 이름을 유지하고 `setStyle`·`loadSourceGeometry` 창구 참조만 비워 해제된 runtime 대표도 자신을 식별하고 편집을 거부한다. runtime 대표 자신은 WFS 표시 조각 목록에 등록하지 않는다. WFS 대표의 원본 참조도 비운다. runtime의 자기 대표는 사용자 OL Feature 접근 호환성을 위해 원본 참조를 유지하되 도형 연결과 구독은 유지하지 않는다. 사용자가 소유한 도형·외부 Feature는 레이어 정리만으로 파괴하지 않는다.

편집용 타일 도형을 해제하면 그 도형의 구독을 끊는다. 이후 전체 도형 요청은 보관한 표시 형상과 최신 개별 편집 스타일을 복원한다. 해제 전에 색·두께를 바꿨다면 복원한 도형과 셰이더 표시가 같은 값을 사용한다. 값으로만 편집한 원본의 복원은 기본 OL 스타일을 강제 생성하지 않으며, 이미 준비된 OL 스타일은 복원 도형에 독립된 객체로 연결한다.

`tests/geometry/vector-binding.test.mjs`·`vector-search.test.mjs`·`native-vector-geometry.test.mjs`에서 연결·스타일·검색·해제와 원본 메서드 보존 계약을 확인한다. `vector-mediator.test.mjs`는 여섯 단일·복합 타입의 완전 원본 재사용, 미사용 원본 회수와 노출·편집 원본 보존, 공개 조회 범위, 레이어별 원본·강조 독립성, OL 스타일 리소스 지연 생성과 부모·자식 레벨별 부분 스타일 편집을 확인한다. 등록 창구의 대표 위임·단독 사용·요청 Promise 동일성·해제·오류 전파와 전체 스타일의 원본별·타일별 단일 처리도 확인한다.
